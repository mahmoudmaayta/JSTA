You are an expert full-stack developer building an MVP web portal for a tourism association.

🎯 GOAL
Build a working MVP web app for the “Tourism Offices Membership & License Renewal Portal” used by:
- Tourism offices (members)
- The association admin (JSTA staff)

The system will:
1. Onboard tourism offices (create account + submit office info + upload required documents).
2. Let the association review and approve accounts (activate username/password).
3. Let offices request **license renewal** and download a PDF file to take to the Ministry.
4. Let offices upload the Ministry-approved document back into the system.
5. Let the association review final uploads and mark renewal as approved/rejected.
6. Provide dashboards for both office and admin.

🔧 TECH STACK (MVP friendly on Replit)
- Backend: Node.js + Express
- Views: EJS templates (SSR – no heavy front-end framework)
- Auth: Session-based auth using express-session
- Database: For MVP, use a simple SQLite DB (via better-sqlite3 or sqlite3) OR an in-memory JS store with a clear TODO to replace with a real DB. Prefer SQLite.
- File uploads: Multer (store files in a /uploads directory)
- Styling: Simple Bootstrap or minimal CSS (no need to over-design)
- Email notifications: Implement using a function stub. Create a `sendEmail(to, subject, body)` function that currently just logs to console with a clear TODO to integrate real SMTP later.

⚙️ HIGH-LEVEL USER FLOWS

There are two main roles:
- **Office User (Tourism Office)**
- **Admin (Association / JSTA)**

### Flow 1: Office onboarding (new office)

1. Association sends an external email with the link to the portal (outside the system scope).

2. The office opens the portal and lands on:
   - Landing page with:
     - “Login” button
     - “Create New Account (Tourism Office)” button

3. When they click **Create New Account**:
   - Show a registration form with:
     - Contact email (will be used as login username)
     - Password + Confirm password
     - Basic contact person name
   - After submitting, do NOT yet consider the account “active”.
   - Immediately redirect them to a multi-section page to fill:
     - Office information form
     - Upload required files for membership/renewal (3 groups described below)
   - Only when they complete this step, the registration is “pending review”.

4. Once they fill the office profile and upload documents:
   - Save all data in DB.
   - Mark office status as `PENDING_APPROVAL`.
   - Show them a message: “Your registration has been submitted and is pending review by the association. You will be notified when your account is activated.”
   - Trigger a notification to admin (in the MVP: a record in admin dashboard + `sendEmail()` stub log).

The association then reviews and approves the office (see admin flow).

### Flow 2: Admin reviews & activates office accounts

Admin access:
- Create a hard-coded first admin user in a seed script or on app start:
  - email: admin@jsta.test
  - password: Admin123 (you can hash it)
- Admin logs in via `/admin/login`.

Admin dashboard pages:
- `/admin/offices`
  - List all offices with columns:
    - Office ID
    - Office trade name
    - Status (PENDING_APPROVAL, ACTIVE, REJECTED)
    - “View” button

- `/admin/offices/:id`
  - Shows:
    - Office legal info
    - Contact info for main office
    - Branches
    - Uploaded documents grouped by category (see below)
  - Admin actions:
    - Approve office → sets status = `ACTIVE`, and triggers `sendEmail()` to office email: “Your account has been approved. You can now log in.”
    - Reject office → sets status = `REJECTED`, optionally with a free-text comment, and triggers `sendEmail()`.

Only `ACTIVE` offices can log in and see their dashboard.

### Flow 3: Office login & dashboard

Once an office is approved:

- They can log in via `/login` using:
  - email (username)
  - password

On successful login (role = OFFICE), redirect to `/office/dashboard`.

Office dashboard should show:
- Office name
- Status (e.g. Active)
- Summary of:
  - Office info (basic details)
  - A list of uploaded base documents (from registration)
- Section: **“License Renewal”**
  - Button: “Request License Renewal”

### Flow 4: License renewal request

When the office clicks “Request License Renewal”:

1. Create a new record in `license_renewals` table with fields:
   - id
   - office_id
   - year (e.g. 2026 – for MVP, hard-code or pick from current year)
   - status: `SUBMITTED` (later: `UNDER_REVIEW`, `APPROVED_FOR_DOWNLOAD`, `MINISTRY_DOC_UPLOADED`, `FINAL_APPROVED`, `REJECTED`)
   - created_at

2. Show a “Request submitted” message in the dashboard.

3. Notify the admin:
   - A new entry appears in `/admin/renewals` list.
   - Call `sendEmail()` stub to log: “Office X requested license renewal.”

Admin side:
- `/admin/renewals`
  - List all renewal requests with:
    - Office name
    - Year
    - Status
    - “View” button

- `/admin/renewals/:id`
  - Shows:
    - Office details
    - Renewal info
  - Admin actions:
    - “Approve for Download” → sets status = `APPROVED_FOR_DOWNLOAD`
    - “Reject” → sets status = `REJECTED` and optional comment

When status is `APPROVED_FOR_DOWNLOAD`:
- Call `sendEmail()` stub for the office: “Your renewal request has been approved. You can download your document from the portal.”
- On the office dashboard, show:
  - A new section: “Download Renewal File for Year XXXX”
  - Download button for a PDF.

For the PDF:
- For MVP:
  - Use a static template PDF stored in `/templates/license_request_template.pdf`
  - Or generate a simple PDF dynamically with `pdfkit` that includes:
    - Office trade name
    - Office ID
    - Year
  - Store or stream it as download.

### Flow 5: Office goes to Ministry and returns

This is outside the system, but from the system perspective:

1. Office downloads the PDF.
2. Office visits the Ministry, gets the official signed/approved document.
3. Office returns to the portal, logs in, opens the same renewal in their dashboard.

Add in the office dashboard:
- List of renewal requests with their statuses.
- For renewals with status `APPROVED_FOR_DOWNLOAD` or `MINISTRY_DOC_UPLOADED`, show:
  - “Upload Ministry-approved document” (file input)

When the office uploads the final document:
- Save the file under `/uploads/ministry_docs/`.
- Link it to that renewal record (e.g. `ministry_document_path`).
- Set renewal status to `MINISTRY_DOC_UPLOADED`.
- Show a confirmation message.
- Notify admin (dashboard + `sendEmail()` stub).

### Flow 6: Admin final review and confirmation

Admin view on `/admin/renewals/:id` when status = `MINISTRY_DOC_UPLOADED`:
- Show link to download/view the uploaded ministry document file.
- Actions:
  - Final Approve → set status = `FINAL_APPROVED`
  - Reject → set status = `REJECTED`, with comment.

When final approved:
- Call `sendEmail()` stub to office: “Your license renewal is now fully approved.”
- Office dashboard shows this renewal as “Approved”.

🧾 REQUIRED FILE UPLOAD CATEGORIES

During initial registration, the office must upload files in three logical groups (they can be multiple files per group):

1. **First group – membership / info forms (INITIAL_FIRST_FORMS)**
   - The internal association forms filled, printed, signed, and stamped:
     - Office information form (like “نموذج معلومات المكتب للعام 2026”).
     - Form for owners, authorized signatories, employees.

2. **Second group – legal/commercial documents (INITIAL_SECOND_LEGAL)**
   - Updated commercial registration (السجل التجاري) showing:
     - Status (e.g., active)
     - Registered trade name
   - If any changes in partners/authorized signatories, attach the updated commercial registration and official letter.

3. **Third group – personal documents (INITIAL_THIRD_PERSONAL)**
   - ID card for new owners/employees.
   - Recent clean criminal record certificate (شهادة عدم محكومية).
   - Recent personal photo.

In the UI, clearly label these sections with text like:
- “First: Membership and Info Forms”
- “Second: Legal / Commercial Documents”
- “Third: Personal Documents”
